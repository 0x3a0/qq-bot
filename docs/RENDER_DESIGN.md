# 渲染设计：行业板块 Treemap 热力图

> 状态：设计契约，实现前需确认
> 目标：一眼看懂「今天哪个行业最强 / 最弱 / 成交最活跃」

## 1. 渲染技术选型：手写 SVG → resvg 转 PNG

**核心决策：不用 matplotlib，不用 headless Chromium。**

| 方案 | 冷启动 | 产物 | 中文字体 | 现代视觉 | 结论 |
|---|---|---|---|---|---|
| matplotlib | ~1-2s | PNG | 需手动指定字体，易踩坑 | 做圆角/渐变很别扭 | ❌ |
| headless Chromium (playwright) | ~3-5s + 300MB 镜像 | PNG | 依赖系统字体 | 最强 | ❌ serverless 不现实 |
| **手写 SVG + resvg-py** | **~50ms** | **PNG** | **字体随 SVG 走** | **圆角/渐变/阴影全部原生支持** | ✅ |

选择理由：
- SVG 是矢量描述，**天然支持圆角矩形、线性渐变、阴影、透明度**——这正是「现代感」的来源，比在 matplotlib 里硬拼要自然得多。
- `resvg-py` 是 Rust 库 resvg 的 Python 绑定，**无 Chromium 依赖，毫秒级**，在 serverless 冷启动友好。
- **字体方案（关键）**：不依赖系统字体，改为在构建期用 Python 把字体文件子集化后以 base64 `@font-face` 内嵌进 SVG。
  这样无论部署到 Vercel / 容器 / 任何 Linux 环境，中文渲染结果**完全一致**，彻底消灭「部署后变豆腐块」这一类问题。字体用 Noto Sans SC（OFL 许可，可自由分发）。
- **Squarified treemap 算法自己实现**（约 60 行），不引第三方图表库——因为要精确控制标注与配色。

## 2. Treemap 布局

- **算法**：squarified treemap（Bruls et al.），保证每个矩形尽量接近正方形，避免出现细长条。
- **面积权重**：**成交额**。这是热力图的通行口径，也符合你给的百度 heat-treemap 页面用 `value=amount` 的参数。
- **板块数量**：A股行业板块有约 496 个（含多级细分），全画会碎成无法辨认的小格。**取成交额 Top N = 40**，其余忽略。美股 11 个板块则全画。
- 矩形间留 **2px 间隙**（gap），形成卡片之间的呼吸感。

## 3. 视觉规范（现代深色风）

```
画布          1600 × 1000 px @2x（输出 3200×2000，兼顾手机缩放清晰度）
背景          #0B0E14（近黑）
标题栏        高 96px：左「A股 行业板块」24px semibold #E6E8EB
              右：数据时间戳 14px #6B7280
副标题行      「成交额加权 · Top 40」14px #9CA3AF
```

### 色阶（红涨绿跌，中国用户习惯）

涨跌幅映射到连续色阶，**非线性**——涨跌幅分布尾部很长，线性映射会让大部分格子挤在中性色。用 `sign(d) * sqrt(|d|)` 做感知均匀映射：

```
+3%   → #E8384F  深红
+1%   → #D6455A
 0%   → #2A2F3A  中性灰（不是白色，深色主题下更和谐）
-1%   → #2E9E6B
-3%   → #10B981  深绿
```

> ⚠️ **A股与美股配色相反**：A股用「红涨绿跌」，美股市场惯例是「绿涨红跌」。
> 这是一个必须显式决定的产品问题——见 §6。

### 区块内部排版（按尺寸分级，避免文字溢出）

| 矩形尺寸 | 显示内容 |
|---|---|
| 大（面积 > 6%） | 行业名 22px semibold + 涨跌幅 30px bold + 成交额 14px |
| 中（2%~6%） | 行业名 16px + 涨跌幅 20px |
| 小（0.5%~2%） | 涨跌幅 14px（行业名太长则截断加省略号） |
| 极小（< 0.5%） | **不渲染文字**，只留色块 |

文字颜色根据背景色亮度自适应（深红/深绿上用白字，中性灰上用浅灰字），保证对比度 ≥ 4.5:1。

### 细节

- 矩形圆角 4px。
- 每个色块叠加一层从上到下的白色 → 透明渐变（透明度 8%→0%），制造轻微的高光，避免纯平色块的廉价感。
- 边界 1px `#0B0E14` 描边，让相邻色块清晰分离。
- 鼠标交互不需要（产物是图片），但保留 hover 态的 SVG 结构以便未来做网页版。

## 4. 尺寸与移动端适配

QQ 群聊内图片会被压缩到屏幕宽度显示。**1600×1000 的 16:10 画布在手机上文字会偏小**。

两个候选：

- **A. 16:10 单张大图**（1600×1000）：信息密度高，适合电脑看；手机上需点开放大。
- **B. 4:5 竖版**（1280×1600）：手机上几乎满屏，文字清晰；但一屏展示的板块数量少。

**建议先用 A**，配合「大/中/小」三级字号保证最小文字不低于 14px（@2x 即 28px 实际像素，手机上可读）。

## 5. 输出与体积

- 格式 **PNG**（官方文档对图片格式口径不一致，PNG 是最保守选择）。
- 目标体积 **< 500KB**。纯色块 + 文字用 PNG 调色板模式（`pngquant` 风格量化）可压到 100KB 以内，远低于 20MB 软限制。
- 若未来需要极致体积，可改用 WebP——但 MVP 不做。

## 6. 待确认的产品问题

1. **美股配色**：跟随 A股都用「红涨绿跌」，还是美股用国际惯例「绿涨红跌」？
   - 建议：**两张图统一用红涨绿跌**。因为同一个群里中国用户看，统一色彩语义比遵守美股惯例更重要；如果混用，用户会误读。
2. **A股取 Top 40 是否合适**？（备选：仅取东财一级行业 ~30 个；或全部 496 个但极小格子不渲染）
3. **文字内容**：是否需要显示领涨股？（会占用空间，但信息价值高）

## 7. 可测试性

渲染层可以完全脱离网络和 QQ 环境测试：

- Squarified 算法：**面积守恒**（所有矩形面积之和 == 画布面积）、**无重叠**、**长宽比上界**——这三个性质可写成断言。
- 色阶映射：给定涨跌幅 → 颜色的确定性断言。
- 文字分级：给定矩形尺寸 → 应显示的内容层级。
- 产物：PNG 尺寸 == 预期、非空、可在 CI 中比对像素直方图防止白屏。
