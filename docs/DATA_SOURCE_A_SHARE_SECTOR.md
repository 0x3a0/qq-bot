# A股「行业板块」行情数据源实测报告

> 目标：为 treemap 热力图提供 **免费、无需 API Key、中国大陆可访问** 的 A股行业板块行情源。
> 实测时间：**2026-09-12（周六）13:29–13:40 CST**，最近交易日为 2026-09-11（周五）。
> 所有结论均来自**真实 HTTP 请求**，原始脚本见 `scripts/verify_*.mjs`。

> ⚠️ 实测环境说明：本机 pwsh 的 HTTPS 全部因 Schannel `SEC_E_NO_CREDENTIALS` 失败（环境问题，非数据源问题），

#### `f6` 是成交额、`f5` 是成交量 —— 实测确认方法

1. **同请求内对比**：`f6=50462477548` 与 `f5=11156547` 相差 4 个数量级；`f6/f5 = 4523` 元/股，若 `f6` 是成交量则均价荒谬。
2. **量级校验**：496 个板块 `f6` 求和 = **5.96 万亿元**，与 A 股单日成交额量级吻合。
3. **跨源校验**：腾讯同口径板块 `volume` 与东财 `f5` 单位换算后一致（详见备选方案）。
4. ⚠️ **注意**：`fltt=2` 只把价格类字段转成浮点，**`f6` 仍是不带小数点的「元」整型**，渲染时需自行除以 1e8 换算成「亿元」。

### 请求示例

**Python（标准库，无第三方依赖）**

```python
import json, urllib.parse, urllib.request

BASE = "http://push2delay.eastmoney.com/api/qt/clist/get"
FIELDS = "f2,f3,f5,f6,f12,f14,f104,f105,f124,f128,f140"

def fetch_all_boards():
    """返回全部 496 个行业板块。共 5 次请求。"""
    boards, total = [], None
    for pn in range(1, 6):                      # pz 上限 100 -> 496 条需 5 页
        qs = urllib.parse.urlencode({
            "pn": pn, "pz": 100, "po": 1, "np": 1,
            "fltt": 2, "invt": 2, "fid": "f3",
            "fs": "m:90+t:2",                   # 行业板块；概念板块用 m:90+t:3
            "fields": FIELDS,
        })
        req = urllib.request.Request(BASE + "?" + qs,
                                     headers={"User-Agent": "Mozilla/5.0"})
        with urllib.request.urlopen(req, timeout=10) as r:
            data = json.loads(r.read().decode("utf-8"))["data"]
        total = data["total"]
        rows = data["diff"] or []               # 越界页可能返回 diff=None
        if not rows:
            break
        boards.extend(rows)
    assert len(boards) == total, (len(boards), total)
    return boards

for b in fetch_all_boards():
    print(f'{b["f14"]:<12} {b["f3"]:>7}%  {b["f6"] / 1e8:>9.2f}亿  '
          f'涨{b["f104"]}/跌{b["f105"]}  领涨:{b["f128"]}')
```

**curl（单页，确认连通性）**

```bash
curl -s 'http://push2delay.eastmoney.com/api/qt/clist/get?pn=1&pz=3&po=1&np=1&fltt=2&invt=2&fid=f3&fs=m:90+t:2&fields=f3,f6,f12,f14'
```

### ⚠️ 三个必须避开的坑（实测）

1. **`pn` 不能省略**：省略 `pn` 时**同一 URL 返回 0 行**（`data.total` 缺失、`diff` 为空）。
   必须显式写 `pn=1..5`。`pz` 传 101/150/200/500/1000 都仍只返回 100 行，**不会报错，只会静默截断**。
2. **`fid` 排序参数被忽略**：`fid=f3` / `f6` / `f12` / `f14` / `f104` 返回**顺序完全相同**（始终 `f3` 降序）。
   **treemap 若按成交额布局，必须在客户端自行按 `f6` 排序。**
3. **`push2test.eastmoney.com` 是假数据陷阱**：HTTP/HTTPS 均返回 200 且结构正常，但**所有数值字段是字符串 `"-"`**：
   ```json
   {"f2":"-","f3":"-","f5":"-","f6":"-","f12":"BK1627","f14":"综合Ⅲ"}
   ```
   不要把它当作容灾备源。

### 时效性说明（重要，需交易时段复核）

- 全部 496 行的 `f124` **一致为 `1789112372` = 北京时间 2026-09-11 15:39:32**，即上一交易日收盘后的快照（`lt:1`）。周末取值稳定属正常。
- 连续两次请求（间隔 4 秒）**100/100 行完全一致**（`f3` 与 `f6` 均无变化），无抖动。
- ⚠️ **域名含 `delay`，极可能是 15 分钟延时行情**。周末无法实测确认。**请在交易时段（9:30–15:00）自行复测**：
  取同一板块的 `f3`/`f6`，与 `qt.gtimg.cn` 或东财网页实时值对比，观察是否滞后约 15 分钟。
  对「按需回复群消息」的场景，15 分钟延时完全可接受；若要秒级实时，需改用下面的腾讯源做交叉判断。

## 限流与容错建议

### 限流实测结论

| 源 | 连发测试 | 并发测试 | 结论 |
|---|---|---|---|
| EM `push2delay` | **30 次连发 0 间隔 → 30/30 成功**，p50 92ms / max 1147ms | **20 并发 → 20/20 成功** | 未见限流，非常宽松 |
| TX `proxy.finance.qq.com` | **25 次连发 → 25/25 成功**，p50 112ms | **15 并发 → 15/15 成功** | 未见限流 |
| Sina `vip.stock.finance.sina.com.cn` | **20 次连发 → 20/20 成功** | 未测 | 未见限流 |

**单次全量拉取耗时实测**：5 页 × 100 行，**总耗时 1.74 秒**，无失败。

### 关于「数字前缀负载均衡」的实测结论 ❌ 无效

已知信息中假设 `1.push2.eastmoney.com` ~ `99.push2.eastmoney.com` 可绕过单域名限流。**实测否定：**

| 域名 | 80 端口 TCP | HTTP 响应 |
|---|---|---|
| `push2.eastmoney.com` | OPEN | **0 字节后 FIN** |
| `1.` `7.` `17.` `48.` `82.` `99.push2.eastmoney.com` | OPEN | **全部 0 字节后 FIN** |
| `push2his.eastmoney.com` | OPEN | **0 字节后 FIN** |
| **`push2delay.eastmoney.com`** | OPEN | **200 OK，完整 JSON** |

- 所有域名的 **DNS 正常解析**（如 `push2.eastmoney.com → 47.112.165.11`、`82.push2. → 61.129.129.196`），**TCP 三次握手也能建立**，但服务器**立刻发 FIN、一个字节都不回**。
- 这不是应用层限流页面（没有 429/403/验证码），而是**连接建立后静默丢弃**，符合 **IP 级封锁**特征。
- **数字前缀与主域返回完全一致 → 说明封锁发生在共享前端入口，前缀负载均衡无法规避。**
- 顺带发现：`push2delay1.eastmoney.com` / `push2delayed.` / `push2hisdelay.` / `push2static.` 返回 **302 跳转**（IIS），非行情接口。

### 容错策略建议

1. **主备双源 + 全量缓存**：以 `push2delay` 为主、腾讯 `getRank` 为备。同一分钟内复用缓存，避免每次群消息触发都打接口。
   - 东财 5 页请求可**并发发出**（实测 20 并发无压力），把 1.74s 压到 ~0.5s。
2. **失败重试**：单页失败重试 1–2 次，退避 0.5s/1s；5 页中若仅 1 页失败，可用其余 4 页（396 个板块）先渲染，**不要整图失败**。
3. **降级顺序**：`push2delay`（496 板块，细） → 腾讯 `hy`（31 板块，粗但一次到手） → 新浪（49 板块）。
   ⚠️ 降级会改变板块数量与涨跌幅口径，建议在图上标注数据来源，避免误导群成员。
4. **空值防护**：正常页面 `f3`/`f6` 均为数字（实测 496/496 无 null、无字符串），但**越界页 `diff` 会变成 `None`/缺失**，代码必须 `data.get("diff") or []`。
5. **校验总量**：断言 `len(boards) == data["total"]`（496），可在数据源口径变动时立即发现。
6. **交易时段外**：周末/夜间 `f124` 保持上一交易日 15:39:32 的快照，属正常，不要据此判定源失效。
